# A. 상단 상태 HUD

> 레이어 **L1 (상시 HUD)**. 전투 내내 항상 보이는 위치·진행·성 상태 정보.
> 플레이어가 "지금 어느 웨이브인지", "앞으로 몇 개 남았는지", "성이 버티는지"를 한눈에 파악하는 축.

## 구성 요소

| ID | 이름 | 노드 경로 | 역할 |
|---|---|---|---|
| A1 | 스테이지명 라벨 | A2 캡슐 내 `chip` (코드 생성) | **"스테이지 N-N"** 포맷 (예: 스테이지 1-1). A2 트래커 캡슐 **윗변에 탭 칩**으로 부착(2026-06-10, 폴더 탭 메타포) |
| A2 | 웨이브 진행 트래커 | `$UI/WaveTracker` (HBoxContainer) | **압축형 노드 스트립** — 앞쪽 3개 + "…" + 최종보스 (카피바라고 참고) |
| A3 | 성 HP 바 | `$UI/CastleBar` (`CastleBar.gd`) | **분절형 성벽 블록**, HUD 스택 맨 아래(전장 경계), **유일한 패배 게이지** |

## 위치 / 크기 (현재)

**상단 HUD 배치 순서** (위→아래, 2026-06-10 탭 칩 통합):
```
        ╭──스테이지 1-1──╮          (A1 탭 칩 — A2 캡슐 윗변에 겹쳐 앉음)
   ╭────┴───────────────┴────╮
   │   [▮][▯][▯] … [♛보스]    │     (A2 압축 트래커 캡슐, 상단 중앙)
   ╰─────────────────────────╯
━━━━ A3 성HP 분절바 ━━━━            (HUD 최하단 = 전장과의 경계선)
```

- **A1** 스테이지명 라벨: 별도 좌측 라벨(`$UI/WaveLabel`) **폐기** → A2 트래커 캡슐 윗변에 **탭 칩**(폴더 탭처럼 살짝 겹쳐 z 위로)으로 통합. `update_wave_tracker()`에서 `wrap`(VBox, separation −7) 안에 `chip`(SHRINK_CENTER·z_index 1·윗모서리 둥글고 아랫모서리 각진 진한 배지) + 기존 `pill` 순으로 코드 생성
- **A2** 트래커: 상단 가로 배치. 현 코드는 웨이브 수만큼 전체 버튼 생성 → **압축 스트립으로 변경 후속**(아래 상태 정의)
- **A3** 성 HP 바: **상단 HUD 스택의 가장 하단**(트래커 아래, 전폭 ~460)에 고정. 0순위 정보지만 화면 최상단이 아니라 HUD 블록 맨 아래 = **전장과의 경계선**으로 두어 "성벽이 전장을 막는" 공간 은유 강화. 현 코드는 월드부착(`$Castle/CastleHP`)이나 **상단 이전 예정** (→ 아래 결정 로그). 월드의 성 스프라이트엔 바 제거, 피격 피드백만 잔존

## 상태 정의

### A2 웨이브 트래커 — **캡슐형 노드 스트립** (2026-06-10 시각 확정, [카피바라고 참고 이미지](참고_카피바라고_웨이브UI.png))

> 트래커 = "런 여정 지도". 앞에 뭐가 오는지(상점/중간보스/보스)를 미리 보여줘 플레이어가 자원 운영을 계획하게 함 — 핵심재미(머리 쓰는 라이트 전략)와 직결. 단, 스테이지 웨이브가 길어질 수 있어 **전체를 다 보여주지 않고 압축**.

**시각 구조 (카피바라고 레퍼런스 차용):**
- **둥근 다크 캡슐**(pill) 안에 노드 배지들이 들어감 — 상단 중앙 정렬, 내용 너비에 맞게 hug(전폭 아님)
- **각 노드 = 원형 배지** + 안에 **종류 아이콘** + 배지 아래 **웨이브 번호**(절대값, 1-based)
- **현재 노드**: 배지 위에 **빨간 ▼ 포인터** + 강조 링/밝은 채움
- 노드 사이는 좁은 커넥터/간격, 캡슐이 내용을 감싼다

**표시 규칙(윈도우) — 항상 4칸 = 슬라이딩 3 + 최종보스 고정 (2026-06-10 확정):**
- **구성**: [슬라이딩 윈도우 3개] + [**최종보스 = 항상 맨 오른쪽 4번째 칸 고정**] = 항상 **4칸**(목표 상시 노출)
- **윈도우 시작 S** = 2웨이브 단위 페이징(짝수 앵커, 0-based: `current_wave − current_wave%2`), 단 끝 근처에선 **`boss_idx−3`까지만** 밀림(클램프) → 끝에서도 4칸 유지
- **"…"** = 윈도우 끝(S+2)과 보스 사이에 건너뛴 노드가 있을 때만(`boss_idx ≥ S+4`). 보스가 윈도우에 붙으면(`boss_idx == S+3`) "…" 없이 **4칸 연속**
- 전체 웨이브 ≤4인 스테이지는 그냥 전부 표시(… 없음)
- **검증 예**(10웨이브, 보스=10): 1·2웨→`①②③ … ⑩` / 3·4웨→`③④⑤ … ⑩` / 5·6웨→`⑤⑥⑦ … ⑩` / 7·8·9·10웨→`⑦⑧⑨⑩`(보스 붙음, … 없이 4연속)
- 앞쪽에선 현재 노드가 윈도우 왼쪽, 끝 근처에선 가운데/끝으로 옴(현재 위치는 가변, 강조로 식별)

**표시 타이밍 — 상시 표시 (2026-06-10 정정):** ~~전투 중 자동 숨김~~ → 폐기. 스폰 라인을 HUD 밴드 아래(y≈150~)로 내려 트래커(y36~100)가 더 이상 적과 겹치지 않으므로 자동 숨김 불필요. 레퍼런스(카피바라고)처럼 **웨이브 트래커 항상 표시**. 전투·상점 구분 없이 `_reveal_wave_tracker()` 단일 호출, 페이드아웃 기계 제거.

**노드 종류 아이콘** (아트 입고 전 임시 = 모노크롬 이모지 `NotoEmoji-Regular`, 입고 시 교체):
| 종류 | 임시 아이콘 | 비고 |
|---|---|---|
| 일반(전투) | 👾 | ⚔(U+2694)는 변형선택자 필요해 모노크롬 폰트서 미표시 → 상위평면 이모지로 교체 |
| 상점 | 💰 | |
| 중간보스 | 👹 | |
| 최종보스 | 💀 | 캡슐 끝 |

**노드 진행 상태:**

| 상태 | 색상 | 표현 |
|---|---|---|
| 현재 | 노랑/밝은 채움 + 빨강 ▼ | 강조 링 |
| 지난 | 회색 흐림 | 페이지 내 현재보다 앞선 노드(예: 2웨이브 때 1번) |
| 남은 | 흰색 | 아이콘 프리뷰(무엇이 올지) |

**미결(플테 조정):** 페이지 단위(현 2웨이브)·중간보스 별도 앵커 고정 여부 / 윈도우 전환 슬라이드 애니.

### A3 성 HP 바 — **분절형 상단 고정바** (2026-06-09 설계 확정)

> 유일한 패배 게이지 = 화면 0순위 정보. 단순 ProgressBar가 아니라 **"성벽" 은유**로, 적이 닿을 때마다 칸칸이 부서져 패배 임박을 체감시킴.

- **형태**: 분절형 성벽 블록. **3칸 고정** (칸당 HP = max_hp / 3 동적). 성벽 강화로 max_hp 증가 시 칸 수가 늘지 않고 **기존 칸이 복구**되는 보강 은유(빈 칸이 다시 채워짐). 미세 피해는 현재 칸 부분채움으로 흡수
- **위급 3단 연출** (긴장 = 시선이 전장에 있어도 주변시로 감지):

  | 단계 | 조건 | 연출 |
  |---|---|---|
  | 정상 | >50% | 차분한 색, 변화 없음 |
  | 경고 | 25~50% | 바 황색 + 느린 맥동 |
  | 위급 | <25% | 바 적색 + **화면 가장자리 붉은 비네트 펄스** |

- **0%가 되면 게임오버** → [E_결과시퀀스](../E_결과시퀀스/) 붉은 오버레이로 전환
- 영주는 HP가 없으므로 이 바가 게임의 유일한 생존 지표 (→ 상위 README "의도된 부재")
- **월드의 성**: HP 바 제거. 피격 시 성 스프라이트 깜빡임 + 낙하 데미지 숫자만 ([F_월드피드백](../F_월드피드백/) 결) — 상단 이전으로 약해진 "저 성이 맞고 있다"는 공간 연결을 보완
- **전장 경계**: 성 HP 바의 하단 모서리(≈y128)가 전장의 상단 경계선이며, 적은 그 아래(y≈150~)에서 스폰·하강하므로 상시 바가 적을 가리지 않는다 (카피바라고 레퍼런스 방식).

## 디자인 의제

- ✅ **A1 ↔ A2 정보 중복** — *해소(2026-06-09)*: A1=스테이지 식별(스테이지 N-N), A2=스테이지 내 노드 진행으로 층위 분리. A1을 트래커 **위**로 올려 "스테이지 1-1" 형식 라벨로 확정.
- ✅ **A1 ↔ A2 시각 분리(축 어긋남)** — *해소(2026-06-10)*: 라벨이 좌측, 트래커가 중앙이라 시각 축이 어긋나던 문제 → A1을 A2 캡슐 윗변에 **탭 칩**으로 부착해 상단 중앙 한 덩어리로 통합(A-2안). 좌측 `$UI/WaveLabel` 노드 제거.
- ✅ **A2 트래커 시인성** — *해소(2026-06-09)*: 압축형 노드 스트립 + 종류별 아이콘으로 격상. 텍스트→아이콘.
- ✅ **A3 HP 바 위치·강조** — *해소(2026-06-09, 구현 완료 2026-06-10, 비주얼 리워크 2026-06-10, 슬림화 2026-06-10)*: 상단 HUD 연속 둥근 바(`$UI/CastleBar`, `CastleBar.gd`) 구현 완료. 월드 `$Castle/CastleHP` 제거. **현재 렌더 = 연속 둥근 바 + 빨간 분절 틱 2개(1/3·2/3 지점) + 좌측 왕관 방패 배지 + 중앙 HP 수치("현재 / 최대")** — `참고_카피바라고_웨이브UI.png`-스타일 레퍼런스 기반 코드-드로우 플레이스홀더(아트 입고 시 교체). 3칸 고정(틱으로 표현), 위험 3단계 맥동 + 비네트 펄스 동작 유지. 바 높이 = ~24 px(`offset_bottom = 128`).
- **명명** — "1-2" 포맷·성(Castle) 명칭 모두 가제. 세계관(마왕성) 적용 시 교체.

## 코드 위치

- `scripts/Game.gd`
  - `_build_wave_tracker()` / `update_wave_tracker()` — 캡슐(`pill`) + 탭 칩(`chip`)을 `wrap`(VBox) 안에 코드 생성. 스테이지 라벨 텍스트(`Loc.t("stage_label")`)도 여기서 칩에 주입(별도 `wave_label` 노드 폐기)

  - `$UI/CastleBar` / `scripts/CastleBar.gd` — 분절형 바 렌더링·위험 단계 맥동·비네트 캡슐화
