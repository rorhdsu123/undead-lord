# 02. 자원 HUD

> 상단 자원 표시. 현재 보유 자원의 *즉각적 가시성*.

## 책임

- 위엄 레벨 + EXP 라디얼 게이지 (좌)
- 왕관 조각 수 (중)
- 해골 수 / 캡 (우)
- 자원 변화 시 갱신

## 레이아웃 (설계 — 2026-06-02 합의)

가로 한 줄, `[위엄] · [왕관] · [해골]` 순서. 모바일 세로 480px 상단.

```
 ╭─◜‾◝─╮
 │ Lv.3 │  위엄        👑 12        💀 3/8
 ╰─◞_◟─╯
   (링 = EXP, 시계방향 충전)
```

- **위엄 = 원형 EXP 게이지 배지** (모바일 표준 라디얼 프로그레스)
  - 링 안에 `Lv.N` 라벨, 배경 링이 EXP만큼 **시계방향으로 차오름**
  - 레벨업 시 링 한 바퀴 → 숫자 +1 (폭죽/연출 자리)
  - 구현: `TextureProgressBar` (`fill_mode = FILL_CLOCKWISE`) 또는 `_draw()` + `draw_arc()` 커스텀
- **왕관·해골 = 숫자 라벨** (기존 형식 유지)

## 현재 상태

| ID | 기능 | 상태 |
|---|---|---|
| B1 | `왕관 조각: N` 라벨 | ✅ |
| B2 | `해골: N / CAP` 라벨 | ✅ |
| B3 | 위엄 라디얼 게이지 (`Lv.N` + EXP 링) | 📐 설계 — 위엄 시스템 구현 시 함께 |
| B4 | 가로 한 줄 레이아웃 재배치 | 📐 설계 — B3과 함께 |

## 코드 위치

- `scripts/Lobby.gd`
  - `crown_label` — `$UI/CrownLabel` (씬에서 주입)
  - `skeleton_label` — `_ready()`에서 동적 생성
  - `_update_crown_label()`, `_update_skeleton_label()` — 갱신
- `scripts/GameSave.gd` — `crown_shards`, `skeleton_count`, `SKELETON_CAP`
  - ⚠ 위엄 필드(`majesty`/`exp`/`level`) **미존재** — B3 구현 전 추가 필요

## 미해결 의제

- **위엄 라디얼(B3)은 단독 구현 불가** — GameSave에 위엄 EXP/레벨 데이터가 없음(D5~D5.2 설계만, 구현 진입 전). **위엄 시스템 구현과 함께** 들어가야 함.
- **캡(Lv.5) 도달 후 링 표현** — 꽉 찬 채 `MAX`/금테/별도 마크 — *폴리싱으로 미룸*(D5.2 "EXP 바 캡 후 처리" 항목과 동일 보류). 이번 설계는 자리만 잡음.
- **자원 4종 넘으면 한 줄 재설계** — 현재 3종(위엄·왕관·해골)으로 가로 한 줄 가능. 영혼은 전투 자원이라 로비 HUD 비대상.
- 자원 변화 애니메이션 (숫자 카운트업, 링 충전 트윈, 반짝임) — 폴리싱 항목
