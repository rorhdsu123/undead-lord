├── assets/                  # 사용 중인 에셋(import됨)
│   ├── characters/          # 스프라이트(necromancer/, enemy_*, boss_*, skeleton_warrior_1~3)

├── Lobby/                   # 로비 설계 문서(D1~D7) — 코드 아님
├── Stage/  devlog/          # 미래 시스템 메모, 개발 로그·WIP
├── docs/                    # 본 문서(아키텍처·게임루프)

## 2. 환경 & 종속성

Godot은 npm식 패키지 매니저가 없다. "종속성"은 **엔진 버전 · autoload 싱글톤 · 에셋 · 프로젝트 설정**으로 구성된다.

### 2.1 `project.godot` 핵심
| 항목 | 값 |
|---|---|
| `config/name` | `undead-lord` |
| `run/main_scene` | `res://scenes/Lobby.tscn` |
| 엔진 features | Godot **4.6**, Mobile 렌더러 |
| 디스플레이 | **480 × 960**(세로), stretch=`canvas_items` |
| 기본 폰트 | `res://assets/fonts/NotoSansKR-Regular.ttf` |
| 렌더링 | `mobile`(VRAM 압축 ETC2/ASTC) |
| Input Map | 커스텀 액션 없음(터치/버튼 UI 기반) |

### 2.2 Autoload 싱글톤 (전역 종속성)
| 이름 | 스크립트 | 역할 |
|---|---|---|
| **`GameSave`** | `scripts/GameSave.gd` | 영구 상태 보관 + `user://save.cfg` 저장/로드. 모든 씬이 진행도·자원을 여기서 읽고 쓴다. |
| **`Loc`** | `scripts/Loc.gd` | 현지화 문자열 테이블(`Loc.t(key)`). 모든 UI 텍스트의 단일 출처. |

> 새 전역 데이터/문자열은 반드시 이 둘을 통해야 한다(흩어진 하드코딩 금지).

### 2.3 외부 에셋
- 스프라이트: **CraftPix** 무료 2D 치비 팩(루트 `craftpix-*`가 원본, 필요분만 `assets/characters/`로 복사).
- 폰트: Noto Sans KR / Noto Emoji.
- 오디오: 미구현(`assets/audio/` 비어있음).

## 3. 핵심 클래스 다이어그램

### 3.1 허브-앤-스포크 구조
`Game.gd`가 **중앙 허브**다. 모든 전투 액터(Player/Enemy/Boss/하인)는 부모 `Game` 인스턴스를 `game` 변수로 **역참조**하고, 콜백·스탯을 그를 통해 읽는다. 명시적 시그널보다 *직접 메서드 호출 + 그룹 조회* 패턴.

```
            ┌──────────── Autoload ────────────┐
            │  GameSave (영구상태)   Loc (문자열) │
            └───────▲───────────────────▲───────┘
                    │ 읽기/쓰기           │ 읽기
        ┌───────────┴────────┐    ┌──────┴───────────┐
        │      Lobby.gd      │    │     Game.gd      │── preload ──▶ WaveData.gd
        │  (Node2D, 경영)    │───▶│  (Node2D, 전투)  │              (static 데이터)
        └────────┬───────────┘ 씬 └──┬──────┬────────┬┘
                 │ owns          전환 │ owns │ owns   │ owns
        ┌────────▼─────────┐   ┌──────▼─┐ ┌──▼─────┐ ┌▼──────────────┐
        │ SkeletonResident │   │ Player │ │Enemies │ │   Minions     │
        │ CastleSprite     │   │  C2D   │ │ (node) │ │   (node)      │
        │ (로비 전용)       │   └───┬────┘ └───┬────┘ └──────┬────────┘
        └──────────────────┘  Skull│      Enemy│Boss        │ SkeletonWarrior
                                (A2D)│       C2D │ C2D        │      C2D
                                     ▼           ▼            │ Arrow(A2D)
                                  적 그룹 "enemies" ◀──────────┘ 하인 그룹 "minions"
        C2D=CharacterBody2D  A2D=Area2D  ──▶ 소유/생성   ◀── 역참조(game)
```

### 3.3 액터 공통 계약 (상속은 안 쓰고 *덕 타이핑*)
Enemy/Boss/SkeletonWarrior는 공통 기반 클래스 없이 같은 인터페이스를 각자 구현:
- `take_damage(dmg)` · `apply_knockback(from, force)` · `apply_slow(sec)` · `_play_anim(name)` · `_on_animation_finished()`
- Boss는 `apply_knockback`/`apply_slow`를 **빈 함수로 override**(면역).
- 액터→Game 콜백: `game.spawn_damage_number()` · `game.spawn_death_effect()` · `game.enemy_died()` / `game.minion_died(pos, type)` · `game.add_souls()` · `game.castle_take_damage()`. ⚠️ 일부는 Game.gd의 **facade**(예: `game.minion_died` → `minion_system.minion_died` 위임) — 액터 인터페이스는 불변, 본체는 자식 컨트롤러(§3.2).

### 3.4 그룹 기반 타겟팅
| 그룹 | 등록 | 조회처 |
|---|---|---|
| `"enemies"` | Enemy·Boss `_ready()` | Player(기본공격·특수기), SkeletonWarrior(타겟), Game(메아리 폭발) |
| `"minions"` | SkeletonWarrior `_ready()` | Enemy(타겟), Game(슬롯 수·일괄 강화) |

### 3.5 알려진 정리 대상 (코드 부채)
- **`SkeletonWarrior._evolve()` / `evolves` / `kill_count` / `EVOLUTION_*`**: 진화 시스템 코드가 남아있으나 **MD6(2026-05-30)에서 진화 폐기** 결정됨(하인=소모품). 제거 대상.
- **`NextWaveButton.gd`**: 구형 컴포넌트.
- **Game.gd 분리 = 2026-06-26 일단락** (4,060→1,832줄, −55%). **콘텐츠 도메인(카드·상점·마물·강화·대사·웨이브 데이터) 전부 분리** → 라이브 콘텐츠 추가가 god object 안 건드림. 패턴=자식 노드 컨트롤러 + 상태는 Game 소유·`game` 역참조(GS2) + 외부 호출자엔 Game facade(GS3). 잔여(저우선·인프라): BattleFX(VFX)·ResourceHUD·Tutorial 미분리(고결합·facade 다수). 코어(웨이브/성/보스/마왕/희생)는 허브에 잔존이 적절. 상세 = [Game_분리_계획.md](./Game_분리_계획.md).
- **Lobby.gd**(~486줄) 비대 → 같은 패턴으로 분리 여지(미착수).
