# 01. 전장 흐름 (Battlefield Flow)

> 전투 한 판의 뼈대 — 웨이브 스폰·진행, 성 HP·게임오버 조건, 상단 웨이브 트래커.
> 다른 모든 기능(공격·하인·카드·보스)이 이 흐름 위에서 돈다.

## 책임

- 웨이브 시작 → 적 스폰 → 전멸 감지 → 다음 웨이브 (또는 상점/보스/클리어)
- 챕터-스테이지-웨이브 좌표 관리 (`WaveData.gd` 테이블 조회)
- 성(Castle) HP 관리, 적 근접 시 피해, HP 0 → 게임오버
- 웨이브 트래커 UI (현재 위치·남은 웨이브 시각화)

## 적 로스터 분화 (다양성 유도, `BD1`, 2026-06-14)

> 하인 소환이 **전역 캡**(종류 자유 편성, [03 MD12](../03_하인_소환/README.md#결정-로그))으로 바뀌며 "단일 종 몰빵"을 막던 종류별 캡이 사라짐. 다양성을 **강제하지 않고 적이 처벌**하도록 적 아키타입을 분화한다.
>
> **원리**: 각 적 아키타입이 *특정 몰빵의 약점*을 정확히 찌른다. 한 웨이브에 이들을 **섞어** 내보내면 어떤 단일 구성도 전부를 못 막음 → "그럭저럭 다 막는 혼합 구성"이 *강제가 아니라 자연 최적해*가 된다. 몰빵은 허용되지만, 그 웨이브의 카운터 적에게 학살당한다.

| 처벌 대상(몰빵) | 처벌 아키타입(가제) | 약점 메커니즘 | 막으려면 필요 |
|---|---|---|---|
| **궁수** 몰빵 | 돌격병(Rusher) / 스웜 | 고속·전선 무시하고 후방 궁수에 직행 / 다수 약체가 몸빵 없으면 수에 깔림 | 탱크·전사 전선 |
| **탱크** 몰빵 | 재생형·고HP 엘리트 / 물량 | 낮은 탱크 DPS로 못 죽임 / 처치 속도 못 따라가 누적·둑 터짐 | 궁수·전사 딜 |
| **전사** 몰빵 | 원거리 카이터 / 폭발(Bomber) | 전사보다 사거리 길게 카이팅하며 갉음 / 뭉친 근접에 AoE 한 방 | 궁수 사거리·분산 |

- **현재 코드 매핑**: `Enemy.gd TYPE_PRESETS`(normal/scout/brute/swarm). 위 아키타입과 대응·확장 필요 — scout≈돌격병? swarm≈스웜? brute≈고HP? (**확인 필요**). **카이터·재생형·폭발형은 신규 추가** 대상.
- **의존성**: 다양성 유도는 위 아키타입들이 **실제 로스터·웨이브 구성에 존재해야** 작동. 또한 몰빵 처벌이 "기습"이 아니라 "읽고 대응"이 되려면 **위협 텔레그래프**([02 영주 전투](../02_영주_전투/) 인디케이터)와 연동 필수.
- **상태**: 방향 박제. **미구현·미밸런싱**(아키타입 수치·등장 곡선 전부 가제).

## 펄스 스폰 (등장 순서·압축, `BD2`, 2026-06-21)

> 기존 "웨이브 시작 시 composition 전부 일괄 투하"를 폐기하고, 적을 **시차(펄스)로 투입**한다. 스폰 패턴은 연출이 아니라 **플레이어 결정을 생성하는 장치** — 이 게임 능동 레버는 ①빌드(웨이브 사이) ②마법 타이밍(낙뢰12s/나팔6s 쿨) ③하인 전선뿐인 저(低)APM 게임이므로, 스폰은 "읽고 → 한 박자 늦게 정확히 대응"하는 결정을 만들어야 한다.

**원리·앵커링**
- **간격 = 마법 쿨에 앵커.** 평웨이브 ~5~6초(나팔6s) → "펄스 하나당 나팔 한 번, 두 펄스당 낙뢰 한 번" 자원 경제 자동 성립. 트리클(끊임없는 한 마리)은 적이 안 뭉쳐 광역 마법을 죽이므로 폐기, **펄스** 채택.
- **압축 = 새 난이도 축.** 후반 난이도를 머릿수가 아니라 **펄스 간격 조이기**(폭주·절정 3~4초)로 표현 → 480px 화면 가독성·타격감 보존. (예: 1-3 W3 swarm 18 단일벽 → 6+6+6@0/4/8s, 동시 화면 ~8 상한.)
- **로그라이트 신선도.** 펄스 구조·역할·수는 손으로 작곡(읽기·재현 가능), **위치·마이크로타이밍만 흔든다**(각 적 `t+rand(0~0.4s)`). 수는 고정 — 밸런스 정합성 보호.
- **역할 순서.** 전위(brute/normal) → 중위(swarm) → 후위(scout, 전위와 살짝 겹쳐 공짜 포킹 방지) → runner는 전선 교전 후 옆구리(현재 시간 기반, 전선상태 트리거는 승급 대기). 절정 웨이브만 펄스 겹침=핀치 작곡.

**난이도 램프 = "정리속도 추월" (플테 검증, 2026-06-21)**
- **레인 디펜스에서 난이도는 "적 누적속도 > 정리속도"가 될 때 체감된다** — 큰 숫자(불릿스펀지)가 아니라 *라인이 휘고 성이 피를 먹는 것*. 초기 펄스는 간격이 정리시간보다 넓어 누적 0 → 평평했고, 결정적으로 **마법 빌드(낙뢰 CDR)가 매 펄스를 통째로 지워** 난이도 곡선을 붕괴시켰다(파워크립).
- **펄스 간격만 줄이는 건 군비경쟁** → durable 해법은 후반 웨이브가 **"AoE 한 방으로 못 푸는 위협"**을 담는 것(= `BD1`):
  - **압축**: 후반 간격을 *줄어든* 낙뢰 쿨(~4.8s) **아래로** → 낙뢰가 다 못 잡아 누적, 쿨 경제 작동.
  - **brute 벽**: 낙뢰 생존·계속 전진 → 군대/단일딜 강제.
  - **runner 우회**: 낙뢰가 덩어리에 묶인 사이 옆구리로 새 **성 타격**(= AoE의 천적·체감 신호).
  - ⚠️ swarm 폭주는 AoE 빌드엔 **먹잇감**(역효과) — swarm은 "비-AoE 빌드 추월"용, AoE 누수는 runner로.
- **검증 결과**: 1-3 풀런서 성 500→250(절반)·"전선 붕괴 시 성 피해"로 빌드 회복력이 난이도로 표현됨. runner 누수를 웨이브별 단조 상승(1-3 W3 3→W7 4→W8 7→W9 9)시켜 **점진 클라이밍** 확보. 1-2도 가볍게 전파(W7 2→W8 3→W9 4). 1-1=FTUE 유지.
- **⚠️ 시스템 caveat (이 작업 밖)**: CDR이 기회비용 없이 -60%까지 가면 마법스팸이 최적해로 남음 → 근본 균형은 [카드풀 키스톤](../../기획문서.md) 트랙서 CDR 상한/기회비용 동반 검토.

**데이터·코드**
- `WaveData.gd`: 웨이브별 `pulses: [{t, spawn:[{enemy,count}]}]`. base 수치·boss 필드는 유지. `wave_enemy_count()`는 pulses 합산(composition fallback).
- `Game.gd`: `start_wave()`가 즉시 스폰 대신 `_spawn_schedule` 구축(`enemies_alive`=총합=조기종료 방지) → `_process` 드레인. `_spawn_scheduled_enemy()` 헬퍼. `end_wave()`/`game_over()`에서 스케줄 clear.
- **수치는 1차안** — Ch1 전 웨이브 펄스 작곡, 1-2/1-3 후반 난이도 곡선 검증·튜닝됨. 1-1/1-2 전반(교습)은 펄스 1차안 유지. 추가 플테 튜닝 대상.

## 위협 텔레그래프 (인-웨이브 경고, `BD3`, 2026-06-26)

> ④ 위협 텔레그래프(02_영주_전투)의 인-웨이브 층. 펄스가 화면에 들어오기 직전 "여기 위험"을 알려 *읽고 한 박자 늦게 대응*(낙뢰 장전·전선 준비)을 만든다 = `BD2`(펄스)·`BD1`(몰빵 처벌)의 짝 인프라.

- **탕탕특공대식 저(低)정보 알람** — "어디에 뭐가 몇" 정밀 인텔이 아니라 **브레이스 한 방**. 종류·수 안 알림(다 떠먹이면 핵심재미 죽음). 표시 = 상단 빨강 그라데이션 글로우(적 진입 방향) + ⚠ 글리프(언어 무관, Loc 불필요) + 가벼운 흔들림. 약 0.8s 안에 페이드.
- **수동 플래그(작곡가 의도)** — 자동 밀도 임계(오발·남발) 기각. `WaveData` 펄스에 `"alert": true`를 찍은 펄스만 경고. 작곡가가 "여기가 핀치"를 직접 배치 → 긴장 의도대로. 1차 시드 = 1-3 W3 침투 꼬리·W8 우회 2파·W9 미끼/침투 3종.
- **코드**: `Game.gd` `THREAT_WARN_LEAD=0.8`(노브)·`_threat_alerts`(펄스 t−lead 스케줄)·`_process` 드레인·`_show_threat_warning()`(VFX). 펄스 위치는 여전히 랜덤(저정보 알람이라 정밀 마커 불필요). 방향성(x 편중)·등급(러시 강도별 강약)은 차후 확장 여지.

## 미해결 의제

- **성 HP 기본값 코드 ≠ 기획** — 코드 `castle_hp = 500`(28줄). 기획·시설 표는 "최대 HP +50/+100" 식 증분 기준이라 시작값 정합 재확인 필요.
- **상점 웨이브 위치** — 기획 §12는 W3·W9. 실제는 `WaveData.gd` 테이블이 단일 진실 — 동기화 확인 필요.
- **적 타입 4종(scout/brute/swarm) 밸런스** — 기획 §12엔 "특이사항"만, 타입별 등장 곡선 미문서화. → **`BD1` 적 로스터 분화와 통합 검토** (현행 4종을 몰빵 처벌 아키타입에 매핑·확장).
- **사전 인텔 (다음 작업, `BD2` 후속)** — "읽고 대응"이 빌드 결정(웨이브 사이)에 작동하려면 **다음 웨이브 구성을 트래커에 노출** 필요. 펄스 스폰은 인-웨이브 미시 대응만 돕고 빌드 결정은 못 도움. 트래커 확장 작업으로 예약.
- **펄스 수치 1차안** — Ch1 펄스 총합은 구 버전과 연속이나 1-3 예산 곡선 jagged(W2≈13→W3≈7 예산) 잔존. 위협 예산(normal1·scout1.2·brute3·swarm0.4·runner1.5)은 **검산 자(ruler)로만** 사용(생성기 아님, 코스트는 플레이어 빌드 따라 변하는 허구). 플테 후 곡선 매끄럽게.
