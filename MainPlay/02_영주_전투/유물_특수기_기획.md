# 유물 특수기 — 전투 참여 재설계 기획서 (가제)

> 목적: 전투 중 플레이어의 **참여감**을 살리기 위해 영주 본체를 전장에서 들어내고, 플레이어 입력을 **"성의 의지로 전장에 권능을 강림"** 시키는 단일 특수기로 재편한다. 특수기 내용은 장착 **유물(가제, relic)** 이 정의한다.
> 이 문서 = 읽기 쉬운 기획 정본. 결정 근거·기각 대안은 [README.md](./README.md) 결정 로그(`RD#`) 참조.
> 작성 2026-06-12 · **설계 단계(미구현)** — 현행 구현(아바타 기반 `A1~A7`)은 교체 전까지 유효. 이름·수치는 전부 가제.

## 1. 핵심 개념

1.1 **문제** — 고정-자동 모델의 수동성. 영주가 성 안에 고정된 채 자동 공격하고, 단조로운 전체화면 특수기 하나만 쓴다. 플레이어가 "전투에 참여하는 느낌"이 약하다. (이 리스크는 [README 2026-06-01]이 이미 예견 → 플레이테스트 판정 "여전히 수동")

1.2 **해결 방향** — 영주 아바타를 **전장에서 완전 제거**한다. 플레이어는 *전장에 선 전투원*이 아니라 **성을 지키는 의지(운영자)** 가 된다. 참여는 지리(위치)가 아니라 **능동 권능(특수기)** 에서 나온다.

1.3 **정체성 = 디펜스.** 이 게임은 디펜스다 — 한 판 안에서 점점 강해지며 성을 지킨다. 따라서 특수기는 *상시 휘두르는 무기*가 아니라 **방어선의 결정적 개입 수단**이다. "어디가 무너지는가"를 읽어 그곳에 권능을 꽂는 것이 곧 재미.

1.4 **로그라이트 빌드 축.** 현재 빌드 시스템(카드=패시브, 키스톤=곱연산)은 전부 자동·수동적이다. 유물은 **플레이어의 능동 표현을 빌드로 정하는** 빠져 있던 축을 채운다. 런마다 장착 유물이 바뀌면 *능동 플레이 방식*이 바뀐다.

## 2. 무대 · 앵커

| 요소 | 정의 |
|---|---|
| 플레이어 | 성의 의지/운영자. 전장에 **몸 없음**. |
| 앵커(몸·HP) | **성**. `castle_hp`가 패배 조건이자 플레이어의 생명. 하단 중앙 `(240, 760)` 유지. |
| 무대 | **세로 레인** 유지. 위(`y<0`)=적 스폰 → 아래 성을 향해 하강. 하인=전선 요격. |
| 도달범위 | **넉넉하게**(사실상 전 화면). 하드 권역(성 둘레 반경 제한)은 기각 — "적이 들어올 때까지 기다리는" 수동성을 재발시키므로(`RD2`). |

## 3. 특수기 = 핵심 능동 동사

3.1 **발현 = "강림"(가제), "휘두름" 아님.** 시전자 몸도 투사체 출발점도 없다. 플레이어가 **조준한 지점에 권능이 직접 발현**한다(from-above). 예: 탭한 곳에 낙뢰가 떨어지고, 역병 지대가 피어나고, 충격파가 터진다.
- 기본 원점 = **표적 강림.** 일부 유물만 "성에서 발사"(from-castle, 예: 부채꼴 충격파)를 *개성*으로 섞는다.

3.2 **순간 깊이 = 조준 + 상황 반응형.**
- **조준** — 누를 때마다 *어디에* 꽂을지 결정.
- **상황 반응형** — 같은 버튼이 **전장 상태를 읽어** 효과가 달라진다(자동·암묵 방식). 적이 뭉치면 광역, 보스가 와인드업 중이면 끊기+치명타, 외곽 탱크엔 넉백. 플레이어는 *모드를 고르는 게 아니라*, 유리한 상황을 *만들고 읽어* 꽂는다.

3.3 **와인드업 치명타 = 전 유물 공통 규칙.** 현재 보스 와인드업 끊기+×2(`Player.gd:177~`)는 특정 특수기의 특수 동작이 아니라, **모든 유물 특수기가 와인드업 중 보스에 적중 시 발동**하는 공통 규칙으로 일반화한다.

3.4 **디펜스 개입의 형태(예).**
- 무너지는 레인 → 넉백으로 시간 벌기
- 뚫린 틈 → 지대로 봉쇄
- 성에 닿기 직전 누수 적 → 강림으로 쳐내기(클러치)
- 보스 와인드업 → 끊기+치명타

## 4. 유물 시스템 (가제)

4.1 **단일 장착.** 런당 **유물 1개**를 장착(복수 로드아웃은 복잡도 때문에 기각, `RD3`). 영혼 = 충전 자원(CotL의 Fervour 대응), 유물 = 발현 능력(CotL의 저주 대응).

4.2 **(다) 통제형/처치형 개성.** 유물마다 디펜스를 *푸는 방식*이 다르다 — 일부는 **통제형**(넉백·둔화·봉쇄로 *시간을 버는* 방어), 일부는 **처치형**(우선 위협을 *지워서* 라인을 구함). 손맛 축(단일/지대/광역, 비용, 리듬)으로도 차별화.

| 유물(가제) | 역할 | 손맛 | 발현 |
|---|---|---|---|
| 낙뢰의 홀 | 처치 | 조준 단일·고화력·고비용 | 표적 강림 |
| 역병 항아리 | 통제 | 조준 지대·지속·중비용 | 표적 강림 |
| 망령의 나팔 | 통제 | 자동 광역·넉백·저비용·짧은쿨 | — |
| 성벽의 포효 | 통제 | 부채꼴 충격파 | 성에서 발사 |

*(위 4종은 손맛 축 예시 — 실제 풀 규모·수치는 남은 작업)*

4.3 **획득·교체 구조(CotL 차용).**
- **장착** = 로비에서(수집·메타 성장). 유물 수집이 로비 메타 목표가 된다(2층 구조의 메타 강화층과 정합).
- **중간 교체·강화** = 새 시스템을 만들지 않고 **기존 노드에 매핑** — 웨이브 사이 카드 선택, 영혼 상점.
- **카드/키스톤** = 장착 유물을 *증폭*(역할 분리: 유물=능동 동작, 카드=패시브 증폭).

## 5. 페이싱

- **템포는 위협 에스컬레이션이 정한다.** 초반 웨이브=한산(가끔 개입), 후반=조밀(쉴 새 없이 triage). 에스컬레이션 자체가 한 판의 곡선.
- **"캐스트 사이"는 공백이 아니다** — 영혼이 차는 동안 *전장을 읽으며 다음 개입을 노리는* 시간 = 디펜스의 긴장.
- 따라서 "N초마다 강제로 눌러 채운다"는 액션 게임식 페이싱은 **기각.** 손이 멈춰도 머리가 움직이게 한다.

## 6. 하인 · 인프라

- **하인 = 자동 지원군.** 외곽 전선을 자동으로 지킨다. 능동 지휘 시스템은 **추가하지 않는다**(복잡도 최소). 딜·라인 유지는 하인·자동에 분담, 플레이어 손은 특수기에 집중.
- **위협 텔레그래프(④) 승격.** 디펜스적 읽기가 성립하려면 "여기 위험하다"가 화면에 보여야 한다. ④ 위협 텔레그래프는 *사치 폴리싱*이 아니라 **이 설계의 필수 인프라**다. → [01_전장_흐름](../01_전장_흐름/) · [07_연출_튜토리얼](../07_연출_튜토리얼/)

## 7. 남은 작업 (의존 순서)

1. **컨트롤 루프 구체화** — 조준 발동 UX(누르면 조준모드 vs 바로 탭), 영혼 충전·비용 모델(캐스트당 소모 vs 게이지), **기존 소환/희생 버튼 거취**(유지·흡수·폐기). ← 다음 논의
2. **유물 시스템 상세** — 초기 풀 규모, 통제/처치 손맛 축 정의, 획득·장착 경로(로비 메타), 중간 교체 노드 구체.
3. **상황 반응형 규칙** — 전장 상태→효과 매핑을 어디까지 규칙화/자동화.
4. **기존 전투 시스템 재매핑** — 자동공격(`A1`) 제거, 패시브 3종(`A4~A6`) 거취, 기존 특수기(`A2`)→기본 유물 흡수, `basic_range`·플레이어 참조 카드/키스톤 재배치(권역 폐기로 range 카드 의미 상실).
5. **UI·아트·연출** — 하단 컨트롤 개편(공격 버튼→유물 특수기·조준), **아트 의뢰 재스코핑**(영주 *전투 모션* 의뢰가 무의미 — 단 로비 존재·유물 컨셉은 유효하므로 *재조정*이지 폐기 아님), "화면 활기" 공백 대응, ④ 위협 텔레그래프 구현.
