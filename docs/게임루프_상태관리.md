# 게임 루프 & 상태 관리 설계

> 코드 기준(2026-06-02). 구조·클래스는 [아키텍처.md](./아키텍처.md) 참조.
> 요약: **두 씬(로비↔전투) + 플래그 기반 제어 + 3계층 상태(영구/런/전역)**. 명시적 FSM은 쓰지 않는다.

---

## 1. 씬 전환 흐름

시작 씬 = `Lobby.tscn`. 로비 ↔ 전투는 `change_scene_to_file()`로 완전 전환(씬 reload)하며, **전환 사이 상태는 autoload `GameSave`가 운반**한다.

```
        ┌─────────────┐  출정(start_chapter/stage 설정)   ┌─────────────┐
        │   Lobby     │ ───────────────────────────────▶ │   Game      │
        │ (경영·강화) │                                    │ (전투·런)   │
        │             │ ◀─────────────────────────────── │             │
        └─────────────┘   결과→로비 / 다음스테이지=Game reload └─────────────┘
                 ▲   둘 다 GameSave(user://save.cfg)로만 상태 공유   │
                 └────────────────── 영구 진행도 ──────────────────┘
```

| 전환 | 트리거 | 운반 상태 |
|---|---|---|
| Lobby → Game | 출정 버튼 / 인트로 종료 | `GameSave.start_chapter`·`start_stage` 설정 후 전환 |
| Game → Game | 결과창 "다음 스테이지"·"재시작" | `GameSave.start_*` 갱신 후 `Game.tscn` 재로드 |
| Game → Lobby | 결과창 "로비" | (저장은 이미 완료, 로비가 `GameSave` 재표시) |

**핵심 패턴**: `Game._ready()`가 `GameSave.start_chapter/stage`를 자기 멤버로 복사한 뒤 **`start_*`를 0으로 리셋**한다 → 출정 시점의 "어느 스테이지" 정보를 일회성으로 전달하는 채널.

## 2. 전투 게임 루프 (웨이브 사이클)

`Game.gd`의 한 스테이지 = 웨이브 배열을 선형 진행. `WaveData.CHAPTERS[ch].stages[st].waves[w]`가 각 웨이브를 정의.

```
start_wave()
  │  WaveData.get_wave(ch, st, w) → type 분기
  ├─ "shop"        → _show_shop() ─(닫기)→ wave+1, start_wave()
  └─ normal/mid_boss/boss
        wave_active = true; 적 스폰; (보스면 보스 입장 연출)
        │
        │  [실시간] Player·SkeletonWarrior·Enemy._physics_process()
        │           플레이어 자동공격 / 하인 추적·공격 / 적 진군·성타격
        │           사용자 입력: 특수기(영혼50) · 하인 소환(영혼)
        ▼
   enemy_died(is_boss)
     ├─ 최종보스 처치(type=="boss") → game_clear()
     └─ enemies_alive == 0 → end_wave()
        │
   end_wave()  (graveyard 회복 적용 → 1.2초 연출 대기)
     ├─ 마지막 웨이브였음 → game_clear()
     ├─ W1 클리어 & 키스톤#1 미선택 → _show_keystones([kingdom, legion])
     ├─ 중간보스 클리어 & #1 선택됨 & #2 미선택 → _show_keystones(축별 2종)
     └─ 그 외 → _show_cards()   (일반 3장)
        │
   _pick_card(i)
     ├─ 키스톤 → _apply_keystone()        (규칙 변경 + 즉시효과)
     ├─ 일반   → _apply_card() + 축 카운트++(lord/summoner)
     ├─ _recompute_keystones()            (카운트 기반 곱 배율 재계산)
     └─ wave+1 → start_wave()
```

### 2.1 웨이브 타입
`normal`(잡몹) · `shop`(영혼 상점) · `mid_boss`(중간보스+잡몹, 왕관 소량) · `boss`(최종보스, 왕관 대량·스테이지 종료).

### 2.2 종료 분기
- **game_clear()**: 마지막 웨이브/최종보스 처치 → 왕관 정산, `GameSave.current_chapter/stage` 다음으로 갱신·저장, 결과창. (1-1 클리어 시 `tutorial_completed=true`)
- **game_over()**: `castle_hp <= 0`(성 함락) → 재시작/로비. *진행도 차감 없음*(이미 획득한 왕관은 저장됨 = 실패 완충).

## 3. 상태 3계층

상태를 수명으로 분류한다. **이 경계가 로그라이트의 핵심**: 런 상태는 매 스테이지 리셋(빌드 새로), 영구 상태만 메타로 누적.

### 3.1 영구 (Persistent) — `GameSave`, `user://save.cfg`
즉시 저장(`save_data()`)되며 씬·세션을 넘어 유지.

| 키 | 내용 | 쓰기 시점 |
|---|---|---|
| `crown_shards` | 왕관 조각(시설 강화 화폐) | 보스 처치 / 시설 구매 |
| `skeleton_count`(·`_seen`) | 해골 충신 수(최대 8) | 보스 처치 / 로비 등장 연출 |
| `facility_levels{}` | 시설 5종 레벨(throne·wall·graveyard·arsenal·banquet, 0~3) | 로비 업그레이드 |
| `current_chapter`·`current_stage` | 진행 해금 위치 | 스테이지 클리어 |
| `intro_seen`·`tutorial_completed`·`first_lobby_visit_done` | 온보딩 플래그 | 각 단계 완료 |
| `start_chapter`·`start_stage` | (운반용) 출정할 위치 | 출정 직전 설정→Game이 소비 후 0 리셋 |

### 3.2 런 (Run) — `Game.gd` 멤버 변수, 씬 reload로 리셋
한 스테이지 = 한 런. 빌드는 매 런 새로(로그라이트).

| 분류 | 변수 |
|---|---|
| 진행 | `current_wave`, `wave_active`, `enemies_alive` |
| 자원 | `souls`, `castle_hp`·`castle_max_hp`, `crowns_this_run` |
| 영주 빌드 | `attack_bonus`, `graveyard_heal`, (Player) `attack_speed`·`basic_range`·스킬 플래그 |
| 하인 빌드 | `max_minions`, `active_minions`, `minion_attack_bonus`, `minion_move_speed_bonus`, `minion_cost_reduction` |
| 카드/키스톤 | `available_skill_cards`, `current_cards`, `lord_card_count`, `summoner_card_count`, `keystone1`, `keystone2`, 파생 `keystone_lord_atk_mult`·`keystone_minion_atk_mult`·`keystone_revive_chance`·`keystone_echo_dmg` |
| 시설 적용분 | `soul_gain_mult` 등 (`_apply_facility_bonuses()`가 GameSave→런으로 1회 주입) |

> **곱 레이어 규칙**: 일반 카드는 더하기로 누적, 키스톤이 켜지면 `_recompute_keystones()`가 *축 카드 수에 비례한 곱 배율*을 파생 변수에 계산. 전투 소비처(Player 데미지 4곳·하인 스폰)가 그 배율을 곱한다. 상세 = [MainPlay/04_성장_경제/카드_키스톤_기획.md §8].

### 3.3 전역 (Global) — Autoload
`GameSave`(영구 상태 보관소 겸 API) · `Loc`(문자열). 어느 씬에서나 직접 접근.

## 4. 제어 방식 — 플래그 기반 (FSM 없음)

명시적 상태 머신 클래스는 없고 **불리언/문자열 플래그**로 흐름을 제어.

| 플래그 | 위치 | 의미 |
|---|---|---|
| `wave_active` | Game | 웨이브 진행 중(입력·공격 활성). start_wave=true / end_wave·game_over=false |
| `_guide_active`·`_freeze_for_special_tip` | Game | 튜토리얼 가이드/정지 |
| `_special_atk_unlocked`·`_special_atk_tip_shown` | Game | 특수기 해금·팁 |
| `_anim_state`(문자열) | Player·Enemy·Boss·SkeletonWarrior | 액터 애니메이션 상태("idle"/"slash"/"hurt"/"die"…) — 사실상 액터별 미니 FSM |
| `is_dashing`·`is_charging_rage`·`overtime_triggered`·`phase3_triggered` | Boss | 보스 패턴 페이즈 |
| `_died_reported` | SkeletonWarrior | 사망 콜백 1회 보장(폭탄 자폭↔피격사 이중 방지) |

> 규모가 더 커지면(교리·이벤트노드 등) 전투 상위 흐름을 명시 FSM으로 승격할 여지 있음 — 현재는 플래그로 충분.

## 5. 틱 · 타이머 패턴

| 수단 | 용도 |
|---|---|
| `_physics_process(delta)` | 이동·충돌·공격 인터벌(액터) |
| `_process(delta)` | UI 갱신(특수기 버튼·소환 슬롯 라벨) |
| delta 누적 타이머 | 자동공격 주기(`basic_timer` 등), 공격 쿨다운 |
| `await create_timer(t).timeout` | 연출 딜레이(웨이브 종료 1.2초 등) |
| `Engine.time_scale` | 히트스톱(타격감, 0.06s 정지) |
| `Tween` | 페이드·이동·색조 등 모든 시각 효과 |
