## 0. 운영자 모델 재배선 (2026-06-18) ⭐ 현재 정본

> 전투가 [운영자 리디자인](../02_영주_전투/유물_특수기_기획.md)으로 바뀌며(영주 아바타 제거 → 유물 마법 2슬롯 + 라이브 골드 군대) 카드 시스템도 재배선됐다. **이 절이 현재 정본**이고 §4~§6 콘텐츠는 이 절을 따른다. 옛 영주/소환사 대칭 모델 기록은 README `KS1~KS8`·git 이력에 보존.

0.1 **카드는 살아남는다(③ 재배선).** 운영자 모델에서 능동 빌드 정체성은 **유물 2슬롯**(로비 선택)이 짊어진다. 하지만 *런 내 빌드 변주*는 카드가 계속 책임진다 — 완전 폐기(②)하면 런 내 변주가 "골드 쓰는 법" 하나로 얇아져 로그라이트 약속과 어긋난다.

0.2 **비대칭 2축.** 옛 영주(7)↔소환사(7) 대칭은 *아바타*를 전제했다(영주 축 = 아바타 자동공격·특수기 증폭). 아바타가 사라지며 대칭이 깨진다. 새 2축:

| 축 | 비중 | 무엇을 증폭 | 콘텐츠 시점 |
|---|---|---|---|
| **`[군대]`** (척추) | 주력 | 자동 군대(라이브 골드 고용)의 *싸우는 방식* | **지금** — 옛 소환사 콘텐츠 대부분 생존 |
| **`[마법]`** (보조) | 경량 | 유물 마법 2슬롯의 reach·범위·쿨·치명타 | **검증 후** — 유물 풀 6~8 확장에 동반 |

0.3 **양적/질적 분리 (카드 ↔ 강화팝업 경계).** 군대를 키우는 길이 카드와 골드 강화(`RD16` 강화팝업) 둘이라 충돌 → 역할 분리:
- **양적**(깡스탯 +%) = **골드 강화팝업**이 소유. "얼마나 세나."
- **질적**(규칙·behavior 변경) = **카드** 드래프트가 소유. "어떻게 싸우나."

같은 "하인 공격 +%"를 두 트랙에서 팔면 중복 인지 + 양쪽 다 밍밍해지므로 깔끔히 가른다.

0.4 **구조는 재배선이지 재설계가 아님.** 곱엔진·`CARD_AXIS`·키스톤·분기점(`Game.gd`)은 축에 무관하게 짜여 있어 그대로 재활용. 이 작업은 *각 카드를 새 축에 다시 꽂는 콘텐츠 재지정*이다.

0.5 **재가동 시점.** ✅ **재가동됨(2026-06-19).** 검증 빌드(`RD12`) 통과(`02 README RD18`) 후 Phase A 게이트 플립 — `Game.gd:699` `if true`→`if false`. 군대 축 카드 드래프트·키스톤(`legion`/`echo`/`horde`) 라이브. 마법 축은 설계만(§6) 비어있어 #1은 `legion` 단일.

## 1. 핵심 개념

1.1 **카드** = 웨이브 클리어마다 3장 중 1장을 골라 빌드를 쌓는다. 런이 끝나면 사라진다(영구 아님).

1.2 카드는 두 종류로 나뉜다.
- **일반 카드** — *질적 강화*. 규칙·behavior를 바꾼다(흡혈·캡+·사거리 등). 반복 등장. 희귀도(일반/레어) 롤. *(깡스탯 +%는 골드 강화팝업으로 이관, §0.3)*
- **키스톤** — *규칙을 바꾼다*. 곱하기 엔진의 스위치. 안 집어도 런을 끝낼 수 있지만, 집으면 빌드가 한쪽으로 꺾인다("선택적").

1.3 **곱하기 엔진** = 키스톤이 켜져 있을 때, 같은 축의 일반 카드를 모을수록 그 효과가 **곱해져** 커진다. 키스톤이 없으면 카드는 그냥 더하기로만 작동한다.

---

## 2. 런 구조

2.1 **런 = 스테이지 1개.** 빌드는 매 스테이지 시작 시 리셋된다(로그라이트).

2.2 **키스톤은 런당 2개**, 정해진 두 분기점에서 *보장 등장*한다(운 롤 아님).

| 분기점 | 시점 | 역할 |
|---|---|---|
| **#1** | W1 클리어 직후 | **빌드 선언** — "이번 런은 어느 축이다"를 정하는 토대 |
| **#2** | 중간보스 처치 | **심화** — 그 축의 출력을 어디에 쏟을지 선택 |

2.3 예외: **최종보스 처치 후 키스톤 없음**(쓸 웨이브가 안 남음). **1-1 튜토리얼 면제**(인지 과부하 방지).

## 3. 곱하기 엔진 규칙

3.1 **카운트 공유 + 출력 분기** — #1과 #2는
- *무엇을 모으나*(카운트 = 같은 축의 일반 카드 수)를 **공유**하고,
- *무엇이 강해지나*(출력)는 **#2에서 선택**한다.

→ 같은 축이라 어느 #2를 골라도 모은 카드가 항상 이득이다(빌드 실패=브릭 없음). #2 선택에 따라 빌드 색깔만 갈린다.

3.2 **수치 모델 = 선형.** 같은 축 카드 1장당 +X%씩 부드럽게 강해진다(계단식 임계 아님). 카드가 랜덤 3중 1택이라, 임계식은 원하는 카드가 안 떠 좌절을 부른다.

3.3 **명시적 태그 UI 없음 → 텍스트 접두어로 실현.** 카드에 배지·아이콘 레이어는 안 만든다. 대신 **카드 설명 첫머리에 축 접두어를 단다**(중립=무접두). **재배선으로 축 명칭 갱신**: `[영주]`→**`[마법]`**, `[군단]`→**`[군대]`**. 예: "뻗는 손아귀\n**[군대]** 하인 사거리 +X", "낙뢰 강화\n**[마법]** 마법 쿨 −X%". 키스톤은 본문에서 그 접두를 가리킨다: "하인 사망 시 폭발. **[군대] 카드를 모을수록** 위력이 커진다".
  - **왜 접두어인가**: 자연어 동사만으로는 *어디까지가 그 축 카드인지 경계가 안 보임*(사용자 지적, 2026-06-02). 접두어가 그 경계를 텍스트로 직접 그어줌. 배지/아이콘보다 가벼운 텍스트 라벨이라 `KS7` 학습코스트 우려와 양립.
  - **시각 처리**: 대괄호 `[ ]`로 감싸고 색상 구분 — `[군대]`=청록 `#0a7d6b`(기존 `[군단]` 색 유지), `[마법]`=보라 `#7b4fc9`(2026-06-19 확정). 구현=`Game.gd` 카드 설명을 `RichTextLabel`(BBCode)로, `Game.gd:_format_axis_tags`가 태그를 color로 감싸 렌더(대괄호는 `[lb]`/`[rb]` escape).

3.4 키스톤 1장의 구성 = ① **0장 기본효과**(아무 카드도 안 모았을 때부터 켜지는 룰 변경) + ② **선형 스케일링**(축 카드 1장당) + ③ **출력 색깔**.

3.5 **트레이드오프는 가볍게.** 대부분 암묵적 기회비용(한 축에 올인하면 다른 축이 약해짐)으로 충분. 무거운 명시 페널티는 일부 강한 키스톤에만.

### 4.3 인벤토리가 드러내는 그림

- **`[군대]` 축은 거의 통째로 생존** — 카드 4장 + 키스톤 3종. 옛 소환사 콘텐츠가 새 척추. 근터 작업 대부분이 여기.

## 5. 키스톤 콘텐츠 — `[군대]` 축 (척추)

> 카운트 풀 = `[군대]` 일반 카드(`minion_count`/`minion_lifesteal`/`minion_range`/`summon_speed`). "모을수록 강해진다"의 대상.
> 이름·수치 전부 가제. 아래 3종은 옛 소환사 키스톤에서 생존(§4.2).

### 5.1 #1 — 「소환 증원」 `legion` (W1 선언, 토대)

| 항목 | 내용 |
|---|---|
| 기본효과(0장) | 소환 슬롯 **+2** ("이번 런은 군세다" 선언. `RD16`/MD12 전역 캡 모델과 연동) |
| 스케일링(질적) | `[군대]` 카드 1장당 슬롯 **+1** — 캡이 군대 카드에 비례해 자란다 (2026-06-18 확정, 상세 근거=README `KS14`) |
| 역할 | **물량 토대** — 빌드를 "군대"로 선언. #2(echo 자폭 / horde 경제)가 그 위에 색깔을 얹음. |

**legion=얼마나 많이(캡) · echo/horde=그 물량으로 뭘 하나** → 세 키스톤이 겹침 없이 조립된다. 옛 "소환사 카드 1장당 하인공격 +8%"(양적, `KS10` 강화팝업과 충돌)는 폐기. 캡 스케일이 "질적"인 근거 = 캡은 깡스탯 +%가 아니라 *판 구조를 바꾸는 규칙*(몸 수↑→커버리지·포지셔닝 변화)이고, §4.1이 이미 `minion_count` 카드를 **"질적(상한)"**으로 분류함과 정합. `minion_count` 카드와 비충돌 — legion은 *모든* 군대 카드를 캡으로 환산하는 곱 스위치(`KS5`), `minion_count`는 그 중 순수 캡 카드(이중 기여). legion+horde "싸고 큰 군대" 콤보는 빌드 비용(키스톤 2+군대 올인→마법·공격 포기)+골드 게이팅+`BD1`(적 로스터 분화)이 받쳐 디제너러트 아님(수치 조절).

### 5.2 #2 — 중간보스 심화 (출력 분기)

같은 카운트를 *무엇에 쏟을지* 고르는 자리. 옛 3종 중 2종 생존(`ritual` 폐기, §4.2).

| 가제 | 기본효과(0장) | 스케일링 | 색깔 | 상태 |
|---|---|---|---|---|
| **「골드 환급」** `horde` | 하인 전사 시 고용비 **50%를 골드로 즉시 환급** | 카드 1장당 환급률 +X% (상한 ~100%) | **물량 회전** (소모전을 골드로 되먹임) | ✅ 생존·**재배선** (2026-06-18) |

### 6.0 설계 원칙 — 유물-비종속 (행동 오버레이)

마법 축 카드·키스톤은 **유물 종류가 아니라 "마법 적중"이라는 *사건*에 건다.** 어떤 유물이든(낙뢰/나팔/이후 확장) 마법이 적중하는 순간 같은 효과를 **덧칠**한다 — `echo`가 *어떤* 하인이 죽든 "하인 사망"에 폭발을 덧칠하는 것과 동형(§5.2).

- **왜 종류 직결이 아닌가.** "처치형 유물 적중 시 연쇄"식 종류 직결은 그 유물을 안 들면 **죽은 카드(브릭)** → §3.1 "브릭 없음"과 충돌. 게다가 유물 2종뿐인 검증 단계엔 콘텐츠 공간이 너무 좁다.
- **그래도 테마는 공명한다.** 「취약」/「처형」(살상 덧칠)은 공격형(처치) 유물과 자연히 끌린다 — 강제로 묶지 않아도 빌드 방향이 정렬(§4.2 2슬롯 정체성과 정합). *(통제 덧칠 「둔화 지대」는 `KS23`로 2단계 보류, §6.3.)*
- **2단계.** 종류 직결 키스톤("낙뢰 연쇄"·"나팔 범위2배"류, §6.1 옛 방향)은 **폐기가 아니라 유물 풀 6~8 확장 때 *추가* 레이어로** 남긴다 — 지금 결정을 미래에 안 가둠.

#### 6.0.1 ✅ 기능 카테고리 태그 채택 — 2단계를 *카테고리 입도*로 앞당김 (2026-06-21, `KS20`)

순수 유물-비종속(위)은 브릭 0이지만 **밋밋**하다(모든 마법 적중에 똑같이 덧칠 → 빌드 정체성·연계 손맛 없음). `area` 1장 검증 중 쇄도를 켜자 마법 연료가 1종뿐이라 **마법 빌드가 굶는** 게 드러남(드래프트 7장 중 magic 1장 = 등장률 ~43%). 해법 = 종류 직결을 *특정 유물*이 아니라 **기능 카테고리**에 거는 중간 입도로 앞당긴다.

- **카테고리는 코드에 이미 있다.** `ABILITY_POOL`의 `alignment` 필드 = 낙뢰 `"처치"`(**공격형**: 피해+크리) / 나팔 `"통제"`(**통제형**: 넉백+슬로우·피해 0). 새 필드 안 만들고 이걸 재사용.
- **왜 지금 안전한가(브릭).** §6.0이 종류 직결을 미룬 이유=얇은 풀의 브릭인데, 검증 빌드는 두 유물 다 장착 → 공격형(낙뢰) 항상 존재 = **브릭 0**. 위험은 미래(유물 풀 확장으로 낙뢰가 선택적이 될 때)뿐. 카테고리 입도라 그때도 카드가 *낙뢰 한 종*이 아니라 *어떤 공격형 유물이든* 받아 위험이 무름. 잔여 위험(통제형-only 빌드)=빌드 정체성 그 자체(카피바라고 "무기가 빌드 강제")이고 **마법 #2(「취약」/「처형」)가 *라인 중립*이라 나팔(통제형) 적중에도 발동해 통제형 빌드도 받친다**(`KS23`로 「둔화 지대」 대체, §6.3) → 두 카테고리 대칭.
- **디리스크.** "카테고리 콤보가 재밌나?"를 *유물 풀 확장 전에* 검증 → 2단계 투자 위험을 먼저 깐다.
- **귀결 = 마법 축이 두 하위 라인으로 갈린다.** **공격형 라인**(낙뢰: 「연쇄 낙뢰」)·**통제형 라인**(나팔: 「제압」, `KS24`·§6.1). #1 「쇄도」(쿨감)·#2 키스톤(「취약」/「처형」, `KS23`·§6.3)은 카테고리 중립(둘 다 받침 — 어느 마법 적중에도 발동). 라인 갈림은 *연계 카드* 층에서(연쇄=공격형 전용 / 제압=통제형 전용), 두 라인 대칭. area 1장으로 굶던 마법 축에 *내부 빌드 선택*이 생김.

### 6.1 일반 카드 (연료 풀)

> 마법을 굴리는 노브 = **어디까지·얼마나 넓게·얼마나 세게**. 「얼마나 자주」(쿨)는 #1 「쇄도」가 흡수(`KS16`, §6.2) — 옛 `cooldown−` 카드와의 양적 중복(`KS10`)을 없애려 카드에서 빼고 키스톤으로 승격. 이 3장이 #1·#2 키스톤이 곱해 키울 "모을수록 강해진다"의 대상. 전부 유물·색 무관(§6.0).

| 카드(가제) | 효과 | 비고 |
|---|---|---|
| **뻗는 마법** `reach+` | 마법 도달 경계 확장(더 멀리 꽂음) | `range_basic` 부활 |
| **넓은 마법** `area+` | 마법 적중 반경 확대 | `range_all` 부활 |
| **강한 마법** `potency+` | 마법 **효과 강도** +%(피해면 피해·넉백이면 넉백·둔화면 둔화) | 신설. *색 중립* — 「피해」로 좁히면 잔류(통제) 빌드에서 약해지므로 "강도"로 정의 |

~~`cooldown−`(빠른 재충전)~~ → **폐기**(2026-06-20, `KS16`): 쿨 단축을 #1 「쇄도」가 토대로 독점 → 카드로 또 팔면 양적 중복. 4번째 노브 자리는 비워 둠(유물 풀 확장 때 신설 검토).

**검증 = `area` 1장 단독·구현 완료·플테 체감 확정(2026-06-20, `KS18`).** 연료 3종 중 검증엔 `area`만 투입한다 — `reach`는 낙뢰 `reach=-1`(전 화면)이라 무효=**조건부 브릭**(유한 reach 유물 들어오는 유물 풀 확장 때 해소), `potency`(피해 %)는 가시성 결여로 플테 체감 실패 → 감각 피드백 레이어 필요해 **2단계 보류**. `area`는 카드당 반경 +25%(가제), `ability_radius_card_mult`로 상점 `radius_mult`와 분리(채널 중복은 검증 통과 후 한쪽 주인 정리·2단계). 낙뢰 착탄 시 **라디얼 그라데이션으로 적중 영역을 표시**해 카드 효과(반경↑)가 눈에 보이게 함(`_spawn_lightning_impact`). 검증 질문("연료 루프가 손맛 나는가")엔 *가장 잘 보이는* 카드로 답한다 = 정합성<체감.

**✅ 공격형 라인 #1 = 「연쇄 낙뢰」(`chain_lightning`) 구현 (2026-06-21, `KS20`·플테 전).** 위 3종(reach/area/potency)은 *색 무관* 연료지만, `KS20`(§6.0.1) 카테고리 태그 채택으로 **공격형 전용 연계 카드** 라인이 열림. 효과 = 낙뢰(공격형=`alignment` "처치") 적중 시 인근의 *미적중* 적에게 연쇄 낙뢰(피해 = 본 낙뢰의 50%·가제), **이 카드 1장당 연쇄 대상 +1**(area처럼 자기 중첩·확정·RNG 없음=`KS6` 정합). 축=`magic` → `magic_card_count` 증가로 **쇄도와 이중 시너지**(연쇄 모을수록 쿨도 짧아짐). 구현: `chain_lightning_targets`(Game.gd) + `_fire_lightning` 본 루프 뒤 연쇄(미적중 적 거리순 N명) + `_spawn_chain_arc`(노랑 지그재그 번개 아크 VFX, "연계" 가독 레이어). 나팔(통제형)엔 무효(공격형 발사 경로에만 붙음). 확률형 갬블(카피바라고 70% 모델)은 튜닝 대안으로 남김. 수치 전부 가제. *(연쇄 탐색·연출·카드 텍스트는 `KS21`에서 진짜 사슬로 정련.)*

**✅ 연쇄 낙뢰 정련 = 방사형 → 진짜 사슬 + 카드 텍스트 가독화(2026-06-21, `KS21`).** `KS20`의 연쇄가 두 문제를 안고 있었음: ①**역시너지** — 후보 풀이 `impact_r`(area로 커짐) *바깥* 적이라 확산을 키울수록 연쇄 후보가 *줄어듦* → 같은 마법 축 두 장(area+연쇄)이 조용히 서로를 깎음(`KS6` "항상 전진"·동축 가산 기대 위반). ②**지각 중복** — 모든 아크가 착탄점 한 곳에서 뻗는 **방사형**이라 "AoE 여러 번"으로 읽혀 `area`(원)와 시각·판타지가 겹침(플테에서 두 카드 구분 인지 실패). **정련**: ⓐ 연쇄를 **착탄점 → 가장 가까운 적 → 그 적에서 다음 → …** 순차 사슬(daisy-chain)로 — 각 홉이 직전 적 기준 탐색이라 `impact_r` 경계와 무관해져 역시너지 소멸. ⓑ 아크를 노드-노드로 잇고 **본 낙뢰 후 `CHAIN_START_DELAY`(≈0.12s) 텀 + 홉당 `CHAIN_HOP_DELAY`(0.08s) 순차**로 "타…닥…닥" 흐름 = 사슬임을 시각이 정직하게 말함. **피해도 각 홉 지연 콜백 안에서** 적용(번개가 그 적에 닿는 순간 50% 피해) — 초기 구현은 피해를 즉시 동기 적용해 VFX만 밀려도 데미지·죽음이 한꺼번에 터져 시차 체감 실패(플테)→피해를 사슬 진행에 동기화. 값 전부 가제·플테 튜닝. ⓒ **출력 노브 확정 = 횟수만(option 1)** — 카드당 연쇄 대상 +1(현행 유지)·발당 피해 50% 고정. 횟수+피해 동시 스케일은 한 카드 두 노브로 과하고 `potency`와 겹쳐 기각, 사슬 감쇠(50→40→…)는 라이트 톤에 과한 계산이라 보류. ⓓ **카드 텍스트를 "면 vs 선"으로 분리** — `넓은 마법`="…모을수록 마법 범위가 커져 더 많은 적을 **덮친다**"(면적·동시·밀집), `연쇄 낙뢰`="맞은 적과 가까운 적 1명을 **감전**(피해 50%)… 모을수록 감전이 **사슬처럼 이어진다**"(선·순차·산개). 단어(덮친다↔감전·이어진다)·단위(불특정 다수↔1명)·피해(풀↔50% 명시)가 셋 다 갈려 지각 중복 해소. "감전"은 플레이버일 뿐 CC 아님("(피해 50%)"로 못박음 — 통제 라인은 나팔). 구현: `_fire_lightning` 연쇄 블록 재작성(`current_pos`+`used` 순차 탐색·피해 즉시·VFX 위치 Vector2 선캡처 후 지연 점등) + `Loc.gd` 카드 2종 문구.

**✅ 통제형 라인 #1 = 「제압」(가제, 미구현) 설계 확정 (2026-06-21, `KS24`).** 「연쇄 낙뢰」의 거울 — **통제형 전용 연계 카드**(나팔 발사 경로에만, 낙뢰엔 무효). 효과 = 나팔 적중 시 **밀려난 적을 N초간 완전 정지**(이동·행동 봉쇄 — 기존 넉백+둔화 위에 *정지*를 얹음), **카드 1장당 정지 지속 +X초**(선형·확정·노브 1개=`KS21` 교훈). 축=`magic` → `magic_card_count` 증가로 **쇄도와 이중 시너지**(쿨도 짧아짐). 가드레일=정지 지속 상한 + **보스·엘리트 저항**(처형의 잡몹 정신과 동형, perma-lock 방지). 가독=밀려나고(변위)+꼼짝 못함(정지) **이중 가시 통제** + 멈춘 무리를 낙뢰·하인·취약·처형이 쓸어담아 *이득(처치)까지 가시*. 구현(미착수): `AbilitySystem.gd:_fire_trumpet`에 정지 적용(`Enemy`/`Boss`에 정지 상태 신규 필요)·통제 VFX(파랑/보라 정지 표시)·`magic_card_count` 스케일·`Loc.gd` 카드 1종. 수치 전부 가제. | **채택 근거 (이데이션 로그=README `KS24`)**: 통제형 라인이 비어 양 라인 비대칭이라 *최소 정체성 카드 1종* 필요(공격형이 「연쇄 낙뢰」 카드로 정체성을 얻은 것과 대칭). 후보 순회 끝에 **「제압」(이동 정지)** 채택 — *레인 디펜스에선 억제가 눈에 보이는 적 행동은 "이동"뿐*이라는 원칙(아래) 때문. 기각: ①넉백 증폭(밀침만)=간접 이득이라 "이득이 안 보임"(피해처럼 명백하지 않음) ②충격 폭발(밀린 적 충돌 피해)=가시적이나 `KS17` "딜 변장"에 근접+코드 비쌈 ③침묵(능력 봉쇄)=잡몹 대다수(잡병·무리·벽)는 봉쇄할 능력이 없어 *다수 상대로 무효*+공격/능력 억제는 "안 맞은 피해"라 부재=비가시. **원칙**: 공격·능력 억제는 *부재*(안 맞은 피해)라 비가시(슬로우가 약했던 함정과 동일) → 이동 억제(정지)만이 "적이 쌓이고→쓸려나가는" 가시 통제. *완전 정지*가 *부분 둔화*보다 통제감 큼("꼼짝 못 해">"조금 느려"). 버스트(짧은 정지)라 둔화 지대의 답답(상시·전역 정체) 회피. 침묵의 anti-캐스터 가치는 후일 보스 대응 유물/카드로 분리.

**갈림 = "어떤 적이 무섭나"**: 취약(강적 증폭) vs 처형(물량 청소). 실제로 무서운 웨이브 구성에 따라 결정이 갈리는 진짜 선택.

**확률 처형 기각 근거 (2026-06-21, `KS23`)**: 처형이 세 보여 "확률 발동"이 제안됐으나 기각. ①**확정(RNG無) 선호** — 연쇄 낙뢰도 확정으로 갔고(`KS21`), `KS6`이 랜덤을 깐 이유(원하는 게 안 떠 좌절·모바일 손실회피)가 그대로 적용. ②**이 트랙의 목적 자체가 인지** — 확률 처형은 *왜 저 적이 죽었는지* 안 읽히고, 투자한 키스톤이 가끔 무효 = 체감 실패(`MD6` "안 읽히는 시스템 = 없는 것"). 강함은 RNG 아니라 **잡몹 전용 + 낮은 확정 문턱**(확정 레버)으로 조인다 — 보스/엘리트 제외가 핵심 안전장치(보스를 깎아 즉살하면 OP). 도박 손맛(카피바라고 70% 모델)은 폐기 아닌 튜닝 대안으로 남김.

**비-피해 제약 정밀화 (2026-06-21, `KS23`)**: `KS17`은 둘째 출력을 "비-피해"로 못박았으나, 그 제약이 우리를 *납작한 경제*(골드 환급=전투 체감 없음) 아니면 *답답한 통제*(둔화=실시간 슬로우 정체)로 몰았다. `KS17`이 여진을 깐 진짜 이유는 "공짜 *플랫 광역 피해*가 결정을 납작하게"였으므로, 제약을 **"플랫 피해 금지 → 규칙변경형 전투효과는 허용"**으로 정밀화. 취약(증폭 — 스스로 딜 안 함, 후속 피해 필요)·처형(문턱 execute — 규칙 변경)은 플랫 피해가 아니라 여진 함정에 안 걸리면서 마법을 *강하게 체감*시킨다.

**「둔화 지대」 보류 근거 (2026-06-21, `KS23`)**: 폐기 아닌 2단계 보류. ①**답답함** — 실시간 레인 디펜스에서 상시·전역 둔화는 적이 기어와 화면 정체("느리게=답답"). 국소 장판·둔화율 캡으로 완화 가능하나 튜닝 외줄이라 검증 단계엔 부담. ②**대안(흡인)은 키트와 모순** — 나팔이 이미 적을 *위로 밀어내는데*(`AbilitySystem.gd:_fire_trumpet` 넉백), 끌어당김(흡인)은 그와 충돌. → 통제 심화 키스톤은 유물 풀 확장 때(2단계). 단 **취약/처형이 나팔 적중에도 발동(라인 중립)**하므로 통제형 빌드도 #2 혜택을 받음 → `KS20`의 "둔화 지대가 통제형 라인 받침"은 이로써 갱신(통제 라인 = 나팔 기본 내장 둔화 + 잠재 둔화 연료, #2 키스톤은 라인 중립 살상 심화).

**배선 (구현 시·미착수)**: `Game.gd:end_wave`에 surge용 분기 추가(`elif wtype == "mid_boss" and keystone2 == "" and keystone1 == "surge": _show_keystones([...])`) → 전용 「전투 전략」 화면(`KS22`)에 자주 배지 2열로 표시(echo/horde가 둘 다 `[군대]`인 것과 동형). `_apply_keystone`/`_recompute_keystones` 신규 분기 + `AbilitySystem` 마법 적중 콜백(취약 표식 부여 / 처형 문턱 판정) + `Enemy.take_damage` 취약 곱. 내부 id 가제.

### 6.4 분기점 통합 — 두 축의 경쟁

마법 축이 켜지면 W1 분기점이 **2축 갈림**이 된다(`KS3`/`KS8` 카운트 공유 구조 그대로):

| 분기점 | 군대 선택 | 마법 선택 |
|---|---|---|
| **#1 (W1)** | `legion`(슬롯 토대) | 「쇄도」(템포 토대) ← *여기서 축 선언* |
| **#2 (중간보스)** | `echo`/`horde` | 「취약」/「처형」 2지 분기(`KS23`·§6.3 — 「둔화 지대」 대체, 2단계 보류) |

→ 지금은 Phase A로 마법 축이 꺼져 #1이 사실상 단일 선택. **검증 통과 후 마법 #1을 켜면 자동으로 2축 분기**가 성립한다(§4.3 "마법 축은 유물 따라 큰다"와 정합). 검증 단계엔 마법 축을 카드 `area` 1장만 두고(`reach`=브릭·`potency`=가시성 결여로 보류, `KS18`), 빌드 변주의 무게는 `[군대]` 축이 진다.

## 8. 코드 구현 기록 (재배선 *이전*, 2026-06-02)

> ⚠️ **아래는 2026-06-18 재배선 이전의 영주/소환사 대칭 모델 구현 기록.** 코드는 살아있으나 운영자 리디자인 Phase A로 **차단 중**(곱엔진·`_show_keystones`·`_show_cards` 호출 우회). 재지정에 따른 변경(폐기/흡수/재배치)은 §7-3, 검증 후 별도 구현. 이 절은 *현재 코드에 무엇이 들어있나*의 참고용으로 보존.

**곱 레이어 분리** — 더하기 스탯(`attack_bonus`/`minion_attack_bonus`)은 그대로 두고, 키스톤 곱은 별도 파생값으로 분리해 카운트 변화 때마다 재계산.
- 상태(`Game.gd`): `lord_card_count`/`summoner_card_count`(축별 카드 수), `keystone1`/`keystone2`(선택된 id), 파생 `keystone_lord_atk_mult`/`keystone_minion_atk_mult`/`keystone_revive_chance`/`keystone_echo_dmg`/`keystone_special_mult`/`keystone_sacrifice_*`.
- `CARD_AXIS`(축 분류 맵), `Game.gd:_recompute_keystones`(픽/선택마다 재계산), `Game.gd:_apply_keystone`(0장 기본효과 즉시 1회 + 상태 설정).
- 전투 소비: 영주 데미지 4곳(`Player.gd` 평타·오라·해골·특수기)에 `* keystone_lord_atk_mult`, 하인 데미지는 `Game.gd:_spawn_minion`에서 `* keystone_minion_atk_mult`(신규 스폰만).

**분기점 등장** — `Game.gd:end_wave`에서 판정: 튜토리얼 면제, `current_wave==0`(W1)→#1, `mid_boss` 처치→#2. `_show_keystones()`는 **키스톤 2장(레전더리·금색) + 일반 카드 1장(커먼 미끼) = 3장**. #1에서 일반 카드를 고르면 축 미선언 → #2도 안 뜸(`keystone1 != ""` 가드).

**동작 훅** — 「소환 증원」 슬롯+2 / 「광전사」 공속×1.5 / 「재앙의 권화」 전 범위×1.4 / 「골드 환급」 하인 사망 부활(`minion_died`) / 「사망 폭발」 사망 폭발(`_spawn_echo_effect`). 사망은 `SkeletonWarrior._report_died()`로 하인당 1회 보장.

**소환사 보강 카드 3종 / 「파멸의 일격」(`doom`) / MD9 희생 + 「제물의 의식」(`ritual`)** — 2026-06-02 구현. `doom`=`keystone_special_mult`(특수기 비용 35·위력 스케일), 희생=`Game.gd:_find_frontline_minion`→`_sacrifice_minion`(MD10 1탭 자동). **재배선으로 `doom`·`ritual`·아바타 키스톤은 폐기 대상**(§4.2). 상세 이력은 git·README KS 로그.
